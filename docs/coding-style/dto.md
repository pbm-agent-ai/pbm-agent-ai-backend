# DTO 스타일 가이드

## 목적
- 요청/응답 모델을 불변 객체 중심으로 단순하고 명확하게 유지한다.

## 기본 규칙
- DTO는 `record`로 작성한다.
- 패키지는 `dto.request`, `dto.response`, 필요 시 `dto.event`로 분리한다.
- 한국어 주석을 사용한다.
- DTO는 데이터 전달에만 집중하고 비즈니스 로직을 넣지 않는다.

## 요청 DTO 규칙
- API 입력값 이름이 명확히 드러나야 한다.
- 필요한 검증 어노테이션을 DTO 필드에 둔다.
- Entity를 직접 받지 않고 request DTO로 변환한다.

## 응답 DTO 규칙
- 외부 노출 필드만 포함한다.
- 내부 식별자/민감정보는 의도적으로 제외한다.
- 공통 응답은 `ApiResponse<T>`로 감싼다.

## 금지 사항
- DTO를 가변 클래스로 작성하지 않음
- DTO에 Repository/Service 의존성을 넣지 않음
- 복잡한 변환 로직을 DTO 생성자에 넣지 않음
